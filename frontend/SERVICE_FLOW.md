# 공개 랜딩과 템플릿 탐색 흐름

## 결정한 서비스 흐름

- `/`는 로그인 여부와 관계없이 히어로 다음에 템플릿 갤러리를 보여 준다. 히어로는 `HomePage`의 별도 섹션이라 이후 디자인을 교체할 수 있다.
- 헤더에서 템플릿 목록과 로그인을 선택할 수 있다. 로그인 상태에서는 내 청첩장과 계정 메뉴를 제공한다.
- `/templates`와 `/templates/:id`는 비로그인 상태에서도 볼 수 있다.
- 상세에서 `이 템플릿으로 만들기`를 누르면 `/create?template=ID`로 간다. 비로그인 사용자는 로그인 후 이 주소로 복귀한다.
- 날짜와 청첩장 주소는 로그인한 제작 단계에서 입력한다. 생성 후 기존 편집기로 이동하며 자동 공개하지 않는다.
- `/invitations`, `/create`, `/e/:id`, `/e/:id/guests`는 `RequireAuth`로 보호한다. 서버의 기존 인증·소유권 검사는 그대로 유지한다.
- 로그인 화면은 `/login`으로 분리했다. 기존 이메일 가입·로그인과 카카오·Google 진입을 유지한다.
- 소셜 로그인 복귀 주소는 sessionStorage에 저장한다. 외부 주소·인증 화면으로의 복귀는 허용하지 않는다. OAuth 콜백은 실패 상태를 제공하며 토큰 쿼리를 브라우저 주소 기록에서 제거한다.

## 템플릿 시각화와 API

- 목록은 기존 `GET /api/templates` 메타데이터 응답을 유지한다.
- 공개 `GET /api/templates/{id}`에 `defaultPageData` JSON 객체를 추가했다. Jackson 2 엔티티 JSON은 DTO의 `@JsonRawValue String`으로 전달한다. 데이터베이스 마이그레이션이나 기존 시드 수정은 없다.
- 상세는 편집기·하객뷰와 같은 `PageRenderer`를 `interactive={false}`로 사용한다. 빈 이름·날짜·장소에는 예시만 표시하며 원본 템플릿과 생성 요청에는 저장하지 않는다.
- 썸네일이 없는 템플릿은 로컬 SVG 식물 일러스트와 종이 커버를 표시한다. 이것은 실제 렌더링 결과가 아니라 디자인 예시임을 목록에 안내한다. 실제 구성은 상세에서 확인한다.
- 찜·검색·필터는 이번 범위에 포함하지 않는다. 외부 이미지나 신규 라이브러리는 추가하지 않았다.

## 2026-10-27 확인 결과

### 이전 편집기 변경

`phase-1/editor-stability`의 미저장 이탈 경고 변경은 사용자 로컬 실행 결과에서 테스트 28개 통과, 빌드 성공, 린트 오류 0개·기존 경고 3개를 확인한 뒤 `549f8b0`으로 로컬 커밋했다. 이 새 기능 브랜치에는 해당 미병합 변경을 섞지 않았다.

### 새 기능 브랜치

GitHub 화면의 최신 main `8e76093`과 로컬 `origin/main`이 일치함을 확인한 뒤 `phase-1/landing-template-flow`를 생성했다. 터미널의 fetch는 DNS 오류로 실패했으며, push·PR·머지는 하지 않았다.

브라우저에서 확인한 항목:

- 로그인·비로그인 양쪽의 공개 랜딩, 비로그인 템플릿 목록과 상세 진입.
- 상세의 제작 버튼을 누르면 선택한 템플릿이 포함된 returnTo 주소로 로그인 화면에 진입.
- 기존 테스트 계정 세션 복원 후 같은 템플릿의 제작 화면으로 복귀. 새 비밀번호 입력이나 실제 소셜 제공자 왕복 로그인은 수행하지 않았다.
- 로그인 상태의 내 청첩장 목록과 제작 폼 표시.
- 데스크톱 4열 갤러리. 390px 너비 same-origin iframe에서 2열 갤러리와 가로 넘침 없음 확인. 실제 모바일 기기 검증은 아니다.
- 런타임 pageerror 수집 결과 오류 없음. 실제 청첩장 생성·수정·공개 요청은 실행하지 않았다.
- 임시 반응형 프레임은 제거했고 원래 계정 세션과 랜딩 화면으로 복귀했다.

### 사용자 로컬 검증 완료

사용자가 첨부한 새 기능 코드의 PowerShell 실행 결과:

- `npm --prefix frontend test`: 22개 통과, 실패 0개.
- `npm --prefix frontend run build`: TypeScript 검사와 Vite 프로덕션 빌드 성공.
- `npm --prefix frontend run lint`: 오류 0개, 경고 5개. 기존 React 경고 3개 외 2개는 URL 검증에서 제어 문자를 의도적으로 거부하는 정규식에 대한 경고였다.
- `gradlew.bat -p backend test --tests "com.invi.api.template.*"`: BUILD SUCCESSFUL. 템플릿 관련 테스트의 결과이며 전체 백엔드 테스트를 의미하지 않는다.
- 이후 사용자가 시크릿 창 기준 `랜딩 → 템플릿 상세 → 만들기 → 로그인 → 선택한 템플릿 유지 → 생성 → 편집·저장 → 새로고침` 흐름을 직접 확인하고 정상 동작한다고 보고했다. 실제 로그인 제공자 종류와 모바일 기기 검증 여부는 별도로 확인하지 않았다.

검증 후 URL 검증 두 곳에 의도와 범위를 설명하는 주석 및 해당 줄에 한정한 `no-control-regex` 예외를 추가했다. 제어 문자 거부 조건을 포함한 런타임 코드는 변경하지 않았다. 에이전트 환경의 권한 제한 때문에 주석 정리 후 린트 경고 개수는 재측정하지 못했다. 이 검증 결과를 바탕으로 로컬 커밋으로 정리하며 push·PR 생성·머지는 하지 않는다.

로컬 PowerShell에서 저장소 루트 기준:

```powershell
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run lint
.\backend\gradlew.bat -p backend test --tests "com.invi.api.template.*"
```

위 명령은 이후 변경 시 재검증에 사용한다. 실제 기기 반응형, 제공자별 소셜 로그인 왕복, 전체 백엔드 테스트, 공개 후 하객 응답은 이번 사용자 확인과 별개의 추가 검증 범위다. 기존 편집기 이탈 경고 커밋 `549f8b0`은 별도 브랜치에 남아 있으므로 해당 변경의 검토·반영도 별도로 진행한다.
