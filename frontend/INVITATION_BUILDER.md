# 청첩장 제작 기능

## 조사 근거

- 공식 기능 명세: https://theirmood.com/mcards/specs (문서 기준일 2026-08-06, 조사일 2026-10-25).
- 명세의 제작·편집 항목은 섹션 드래그 정렬, 실시간 미리보기, 샘플 문구, 글꼴·글자 크기 설정을 설명한다.
- 공개 샘플: https://theirmood.com/mcards/sample. 샘플에서 제작을 시작하는 버튼과 참석 확인 양식을 직접 확인했다. 편집기 진입에는 로그인이 필요해 경쟁 서비스의 로그인 내부 편집기는 확인하지 않았다.
- 구현은 관찰한 동작 패턴을 참고했으며 경쟁사의 코드·문구·사진·브랜드 자산은 사용하지 않았다.

## 구현 범위

기존 `/e/:id` 경로에 `InvitationBuilderPage`를 연결한다.

- 네 가지 자체 디자인 프리셋, 배경·강조 색상, 명조·고딕과 글자 크기 3단계.
- 신랑·신부 이름, 예식 시간, 대표 사진 URL, 초대 문구와 자체 샘플 문구 3종.
- 예식장·주소·교통 안내 직접 입력, 기존 6역할 계좌/대체 메시지 편집.
- 이미지 URL로 갤러리 추가(최대 100장), 사진 순서 변경·삭제, 2열·3열·가로 슬라이드.
- 섹션 드래그 정렬 및 키보드/모바일용 위·아래 버튼, 표시/숨김 설정.
- 변경 상태 표시, 새로고침 및 헤더 링크 이탈 시 미저장 경고, 수동 저장.
- 공개 전에 표시되는 필수 정보 확인, 저장 성공 후 공개, 공유 링크 복사/열기. 저장·공개 중 중복 요청 방지.
- 공개 화면과 편집기 미리보기에서 동일한 `PageRenderer` 사용. 미리보기에서는 RSVP/방명록 제출 요청을 보내지 않는다.
- 안전한 http/https 이미지 주소 및 허용된 디자인 토큰만 렌더링. 글자와 배경의 대비가 낮으면 읽을 수 있는 색으로 보정.

## 저장 계약

`pageData.blocks`의 `order`, `visible`, `content`를 그대로 사용한다. 전역 디자인은 선택적인 `pageData.design`에 저장한다. 저장할 때 전체 pageData와 기존 블록 필드를 보존하므로 알 수 없는 확장 필드를 제거하지 않는다.

기존 JSONB API가 전체 JSON을 저장·반환하므로 백엔드 스키마 변경이나 DB 마이그레이션은 없다. 이전 템플릿은 hero의 기존 색상·글꼴 토큰을 읽어 호환한다. 디자인 선택은 내용·사진·정렬을 덮어쓰지 않는다.

## 이번 범위에서 제외

결제/유료 이용권, 카카오 공유 SDK, QR 생성, 예식장 검색 API, 지도 자동 완성, 음악·오프닝 애니메이션, RSVP 질문 추가 및 하객 사진 수집은 구현하지 않았다. R2 파일 업로드 UI는 기존 프로젝트의 비활성 정책을 유지하며, 이미지 URL 입력만 추가했다. 예식일은 생성 시 선택하고, 편집기의 [변경] 버튼으로 초안 저장과 별개로 즉시 바꾼다(무료 청첩장 만료 기준, `docs/INVITATION_EXPIRY.md`).

## 검사

Node 24 또는 22.18 이상 권장.

```sh
npm test
npm run lint
npm run build
```

`src/editor/model.test.ts`는 순서 이동·불변성·확장 필드 보존, 숨김, 기존 템플릿 호환, 대비, URL 제한, 공개 전 검증을 검사한다. 앱 TypeScript 설정은 테스트 파일을 제외한다.

실행 환경에서 테스트 러너의 프로세스 격리가 제한되면 Node의 격리 없는 실행 또는 CommonJS 테스트 하네스로 동일 테스트를 실행할 수 있다. 타입 검사는 캐시 파일 쓰기가 제한된 환경에서 `tsc -p tsconfig.app.json --noEmit --incremental false`로 실행할 수 있다.

자동 저장은 아니므로 편집 후 저장 버튼을 눌러야 한다. 기존 공개 청첩장을 저장하면 같은 공개 주소에 바로 반영되는 기존 API 동작을 유지한다.

## 2026-10-26 저장·공개 실패 처리 검증

### 보완 내용

- 저장·공개 요청 흐름을 `src/editor/persistence.ts`로 분리했다. 하나의 잠금이 저장 시작부터 공개 응답까지 유지되며 같은 화면의 중복/혼합 요청을 막는다.
- 저장 실패 시 draft와 저장 기준값을 교체하지 않고, 공개 요청을 보내지 않는다.
- 저장 성공 후 공개 실패는 전체 저장 실패와 구분한다. 저장된 내용은 반영하되 공유창을 열지 않고 재시도를 안내한다.
- 공개 응답이 HTTP 성공이어도 `status=PUBLISHED`가 아니면 공유 성공으로 취급하지 않는다.
- 미리보기 전용 화면에서는 편집 패널이 숨겨져 오류도 보이지 않던 문제를 재현하고 수정했다. 오류 안내를 공통 영역으로 옮기고 재시도 버튼을 추가했다.
- 재시도는 이전 요청의 스냅샷이 아니라 현재 편집 내용을 다시 저장한 뒤 공개한다.

### 검증 결과

- `model.test.ts` 기존 6개 + `persistence.test.ts` 신규 11개, 총 17개 통과. `npm test`가 두 파일을 실행하도록 변경했다.
- 이 세션의 표준 Node ESM 실행은 파일시스템 루트 조회 권한으로 차단되어, 동일 테스트 소스를 임시 CommonJS 하네스로 변환해 실행했다. 테스트 본문의 검증 내용은 바꾸지 않았다.
- 앱 TypeScript 검사 통과. Oxlint 오류 0개, 기존 경고 3개 유지.
- 실제 편집 UI에 브라우저 한정 응답 교체를 적용해 다음을 확인했다. 테스트 청첩장의 PUT/POST만 가상 응답으로 처리했으며, 테스트 종료 후 응답 교체를 제거하고 원래 화면으로 복귀했다.
  1. 저장 503: 입력 유지, 미저장 상태 유지, 공유창 닫힘, 공개 요청 0회.
  2. 네트워크 오류: 입력 유지, 버튼/편집 잠금 해제, 재시도 가능.
  3. 저장 200 + 공개 500: 저장 완료와 공개 미확인 상태를 구분하고 공유창을 열지 않음.
  4. 공개 실패 후 이름을 수정해 재시도: 수정본을 다시 저장한 뒤 공개, 성공 응답 이후에만 공유창 열림.
  5. 지연된 저장 중 저장/공개 연속 클릭: 저장 1회, 공개 0회, 응답까지 입력 잠금, 완료 후 잠금 해제.
  6. 지연된 공개 중 공개/저장 연속 클릭: 저장 1회와 공개 1회, 공개 완료 전 공유창 닫힘, 응답 후 잠금 해제.
- 검증 전후 공개 API 응답을 비교해 원본 청첩장 데이터가 동일함을 확인했다. 실제 저장·공개 쓰기 요청은 전송하지 않았다.
- 수정 후 Vite 번들 검증은 이 세션의 제한 환경에서 진행되지 않아 완료 여부를 확인하지 못했다. 앞서 사용자가 확인한 빌드 성공은 이번 수정 이전 결과다. 일반 로컬 터미널에서 `npm test`, `npm run build`를 다시 실행하면 된다.

### 범위와 한계

입력 유지는 현재 열린 화면 기준이다. 새로고침 후 복구를 위한 로컬 초안 저장, 영구 무응답의 타임아웃, 다른 탭/기기에서의 동시 편집 충돌 처리는 이번 변경에 포함하지 않았다. 프론트 단일 실행 잠금은 같은 편집기 인스턴스 안에서만 적용된다.

## 2026-10-26 미저장 이탈 방지

### 변경 내용

- `BrowserRouter`를 React Router의 Data Router(`createBrowserRouter`/`RouterProvider`)로 바꿔 공식 `useBlocker` API로 내부 이동과 브라우저 뒤로/앞으로 가기를 처리한다. 기존 경로와 인증 방식은 유지한다.
- 미저장 변경이 있으면 같은 확인창에서 계속 편집, 저장하고 이동, 저장하지 않고 이동을 선택한다. 저장에 실패하면 확인창 안에도 오류를 보여 주고 편집기에 머무른다.
- 저장/공개 처리 중에도 이동을 차단한다. 계속 편집은 이동만 취소하며 진행 중인 요청을 취소하지 않는다. 늦게 저장 응답이 와도 취소한 이동을 다시 실행하지 않는다.
- 저장하고 이동은 목적지 키를 확인하고, 같은 목적지가 여전히 차단 상태일 때만 진행한다. 중복 클릭은 하나의 저장만 실행한다.
- 저장 내용이 깨끗하고 처리 중인 작업도 없으면 경고하지 않는다. 같은 경로의 hash 이동은 차단하지 않는다.
- 새로고침·탭 닫기·외부 문서 이동은 `beforeunload`의 브라우저 기본 경고를 사용한다. 미저장 상태와 처리 중 상태 모두 경고 조건에 포함한다.
- (2026-10-30 main 이식 시 추가) 처리 중이거나 실패한 대표·갤러리 사진도 이탈 차단·경고 조건에 포함한다. 이 상태에서는 저장이 거절되므로 확인창은 "저장하고 이동"을 숨기고 계속 편집 또는 저장하지 않고 이동만 제시한다. 판단 규칙은 `navigation.ts`의 `leaveDialogMode`/`canSaveBeforeLeave`로 테스트한다.
- (2026-10-30 추가) 확인창이 cancel 이벤트 없이 닫혀도(예: Chrome에서 사용자 조작 없이 Escape를 연달아 누름) 차단된 이동을 취소해 라우터가 차단 상태로 남지 않게 한다.

### 검증

- 기존 17개와 `navigation.test.ts` 11개, 총 28개 통과. 제한 터미널에서는 기존과 동일하게 임시 CommonJS 하네스로 원본 테스트 소스를 실행했다.
- 앱 타입 검사 통과. 린트 오류 0개, 기존 경고 3개 유지.
- 실제 브라우저에서 뒤로 가기/앞으로 가기, 내부 응답 관리 링크와 홈 링크, 이동 취소 시 입력 유지, 명시적 버리기, 원래 값으로 복원 시 경고 해제를 확인했다.
- 테스트 청첩장의 저장 응답만 브라우저에서 교체해 저장 실패 후 머무름, 재시도 성공 후 이동, 저장 중 이동 취소 후 늦은 응답이 와도 머무름을 확인했다. 저장만 수행하며 공개 요청은 0회였다.
- 미저장 변경이 없는 상태에서 공유 요청이 처리 중인 경우에도 이탈 차단과 beforeunload 경고 조건이 활성화되는 것을 확인했다.
- beforeunload는 취소 가능한 이벤트의 defaultPrevented 여부로 확인했다. 실제 기본 경고 표시 여부와 문구는 브라우저 정책을 따른다.
- 응답 교체를 해제하고 원래 편집기로 복귀했으며, 공개 API 응답의 검증 전후 일치를 확인했다. 실제 청첩장 데이터는 수정하지 않았다.

### Git 및 남은 확인

처음에는 `phase-1/editor-stability`에서 작업했고(2026-10-27, 테스트 28개 통과), push되지 않은 채 남아 있었다. 2026-10-30에 최신 main 위로 `phase-1/unsaved-navigation-guard`(PR #14)로 이식했다. 이식하면서 그 사이 main에 추가된 라우트(`/templates`, `/login`, `/create`, `/invitations`, `RequireAuth`)와 `RouteScrollReset`을 Data Router의 공통 레이아웃 라우트로 옮겼다. 이식 후 프론트 테스트 98개 통과, 타입 검사·빌드 성공, 린트 오류 0개와 기존 경고 3개를 확인했다. 로컬 브라우저에서는 테스트 계정과 테스트 청첩장으로 로고 링크 차단, 계속 편집, 저장하고 이동(API 저장 확인), 앱 내부 이동 후 뒤로 가기와 저장하지 않고 이동을 확인했다. 사진 처리 중 확인창은 브라우저에서 재현하지 않았다.

이 기능은 이탈 경고이지 자동 저장/복구가 아니다. 사용자가 저장하지 않고 이동을 선택하거나 브라우저가 비정상 종료되면 미저장 내용은 복구되지 않는다. 모바일 운영체제의 강제 종료 등에서는 beforeunload가 실행되지 않을 수 있다.
