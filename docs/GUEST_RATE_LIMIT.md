# 하객 쓰기 요청 제한 (RSVP · 방명록)

로그인 없이 열려 있는 `POST /api/invitations/{id}/rsvps`, `POST /api/invitations/{id}/guestbook`의 스팸·폭주를 막는다. `GuestWriteRateLimiter`(메모리, 슬라이딩 로그)가 담당한다. 고정 창과 달리 창 경계에서 한도의 2배가 몰려 통과하지 않는다.

## 규칙

- RSVP와 방명록은 따로 센다.
- **하객(접속 주소) 한도**: 같은 청첩장에 같은 주소로 10분에 10건. 예식장 Wi-Fi나 통신사 NAT 때문에 여러 하객이 같은 주소를 쓰는 경우가 많아 넉넉하게 잡았다.
- **청첩장 전체 한도**: 청첩장 하나에 1시간에 300건. 주소를 바꿔 가며 보내도 넘을 수 없는 상한이다.
- 한도를 넘으면 `429`와 `Retry-After`(초), 메시지 "요청이 많아 잠시 막혔어요. 잠시 후 다시 시도해 주세요."를 돌려준다. 하객 화면은 이 메시지를 그대로 보여 주고 입력한 내용은 유지한다.
- 거절된 요청은 어느 한도에도 세지 않는다. 그래서 한 사람이 계속 두드려도 청첩장 전체 한도를 다 써 버리지 못한다.
- 청첩장을 찾은 뒤에만 센다. 존재하지 않는 id나 **공개 전(DRAFT) 청첩장은 404**이고 세지 않는다. 하객은 공개된 청첩장에만 쓸 수 있다.
- 저장이 실패하면(예: DB 콜드 스타트) 그 요청 몫을 되돌려서, 재시도한 하객이 아무것도 저장되지 않았는데 막히지 않는다.
- 만료된 기록은 1분에 한 번만 정리한다. 추적 표가 가득 차도 요청마다 표 전체를 훑지 않는다.

## 접속 주소의 한계 (Render)

- `https-test` 프로필은 `server.forward-headers-strategy=framework`라서 `X-Forwarded-For`의 첫 값이 접속 주소가 된다.
- Render 프록시는 클라이언트가 보낸 `X-Forwarded-For`를 지우지 않고 뒤에 덧붙인다는 사용자 보고가 있다. 그 경우 첫 값은 위조할 수 있다. 따라서 하객 한도는 **일반 사용자 반복 제출 방지용(최선 노력)**이고, 청첩장 전체 한도가 실제 상한이다.
- 주소를 계속 바꾸는 공격으로 추적 표가 가득 차면(기본 10,000개), 만료된 항목을 비운다. 그래도 가득 차 있으면 새 주소는 하객 한도 없이 통과하고 청첩장 전체 한도만 적용한다. 정상 하객까지 전부 막히지 않게 하기 위해서다.
- 이 위조 가능성 때문에, 한 사람이 주소를 바꿔 가며 청첩장 전체 한도(1시간 300건)를 다 써서 그 시간 동안 다른 하객을 막을 수 있다. 주소 출처를 확정하기 전까지 남는 위험이다.
- `native`(Tomcat RemoteIpValve, 오른쪽부터 신뢰 프록시를 건너뛰는 방식)로 바로 바꾸지 않은 이유: Render 앞단 마지막 홉이 공인 IP(예: Cloudflare)라면 모든 하객이 같은 주소로 묶여, 붐비는 예식에서 정상 하객이 단체로 막힌다. 위조 가능한 상태보다 더 나쁘다.

### 주소 출처 확인 절차 (실서비스 전)

테스트 서버에서, 테스트 청첩장에만 한 번 실행한다. 생성된 테스트 응답은 확인 후 지운다.

1. 같은 PC에서 `X-Forwarded-For: 203.0.113.1`을 붙여 RSVP를 10번 보낸다.
2. 11번째를 `X-Forwarded-For: 203.0.113.2`로 보낸다.
   - **201** → 앱이 보는 주소가 클라이언트 헤더의 맨 앞 값이다(위조 가능). `native` + `server.tomcat.remoteip.internal-proxies`로 Render 프록시만 신뢰하도록 바꾸는 것을 검토한다.
   - **429** → Render가 맨 앞 값을 실제 주소로 덮어쓴다. 지금 설정을 유지한다.
3. 결과를 이 문서에 기록한다.

## 설정 (`invi.rate-limit.guest-write.*`)

| 속성 | 기본값 |
|---|---|
| `enabled` | `true` |
| `per-client` / `client-window` | `10` / `PT10M` |
| `per-invitation` / `invitation-window` | `300` / `PT1H` |
| `max-tracked-clients` | `10000` |

- 카운터는 서버 메모리에만 있다. 재시작(Render Free 휴면 후 기동 포함)하면 초기화되고, 인스턴스가 여러 개면 각자 센다. 현재 무료 단일 인스턴스 기준이다.
